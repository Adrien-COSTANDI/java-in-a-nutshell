\# Critères d'évaluation



\## 1. Exactitude



Vérifier :



\* comportement réel du code ;

\* syntaxe ;

\* types ;

\* exceptions ;

\* API utilisées ;

\* règles du langage ;

\* explications correspondant réellement au comportement du code.



Une affirmation pédagogique simplifiée doit être signalée comme telle uniquement si elle risque de créer une mauvaise compréhension.



\## 2. Bonnes pratiques



Évaluer notamment :



\* nommage ;

\* responsabilité des classes et méthodes ;

\* encapsulation ;

\* immutabilité lorsqu'elle est pertinente ;

\* gestion des erreurs ;

\* exceptions ;

\* ressources ;

\* collections ;

\* API modernes ;

\* lisibilité ;

\* testabilité ;

\* séparation des responsabilités ;

\* complexité inutile.



Ne pas transformer une préférence personnelle en règle absolue.



\## 3. Java moderne



Évaluer si le cours explique ou utilise de manière pertinente les fonctionnalités modernes appropriées au niveau du cours, notamment lorsque cela apporte une réelle valeur pédagogique.



Exemples de domaines à examiner :



\* records ;

\* sealed classes ;

\* pattern matching ;

\* switch expressions ;

\* text blocks ;

\* var ;

\* interfaces fonctionnelles ;

\* lambdas ;

\* Stream API ;

\* Optional ;

\* collections modernes ;

\* try-with-resources ;

\* concurrence ;

\* virtual threads ;

\* modules, si pertinents ;

\* nouveautés spécifiques à Java 25 lorsqu'elles sont pertinentes pour le programme.



Ne pas introduire une fonctionnalité uniquement parce qu'elle est nouvelle.



\## 4. Progression



Pour chaque concept important, vérifier :



\* prérequis ;

\* introduction ;

\* explication ;

\* exemple ;

\* pratique ;

\* réutilisation ultérieure.



Rechercher les "sauts cognitifs".



\## 5. Exercices



Évaluer :



\* cohérence avec les notions enseignées ;

\* difficulté ;

\* formulation ;

\* objectifs ;

\* présence éventuelle d'indices ;

\* progression ;

\* possibilité de vérifier la solution.



Un exercice ne doit normalement pas demander une compétence qui n'a jamais été introduite sans que cela soit volontairement présenté comme un défi.



\## 6. Clarté



Rechercher :



\* phrases inutilement longues ;

\* paragraphes excessifs ;

\* termes non définis ;

\* explications circulaires ;

\* exemples sans explication ;

\* explications sans exemples ;

\* ambiguïtés ;

\* jargon inutile.



\## 7. Cohérence



Vérifier la cohérence :



\* terminologie ;

\* conventions de code ;

\* niveau de détail ;

\* noms ;

\* structure des chapitres ;

\* progression ;

\* exemples ;

\* conventions Markdown.



\## 8. Documentation Obsidian



Vérifier :



\* liens internes ;

\* liens cassés ;

\* notes orphelines ;

\* navigation ;

\* structure ;

\* titres ;

\* index ;

\* tags ;

\* références croisées.



La structure doit servir l'apprentissage plutôt que l'organisation technique du vault.
