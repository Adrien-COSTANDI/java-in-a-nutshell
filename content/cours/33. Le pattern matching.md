Le **pattern matching** (filtrage par motif) est une fonctionnalité qui a été introduite progressivement dans Java à partir de la version 16. Elle permet d'écrire du code plus concis et plus sûr quand on travaille avec des hiérarchies de types. Autrement dit : fini les tests de type suivis de casts fastidieux, le langage s'occupe de tout !

## instanceof pattern matching

Avant Java 16, pour vérifier le type d'un objet et l'utiliser, on devait écrire :

```java
// Avant
Object obj = "Hello World";
if (obj instanceof String) {
  String s = (String) obj; // cast manuel
  IO.println(s.length());
}
```

Avec le pattern matching, on combine le test et le cast en une seule étape :

```java
// Après
Object obj = "Hello World";
if (obj instanceof String s) {
  IO.println(s.length()); // s est directement disponible
}
```

Regardez : plus de cast à la main ! Le pattern `String s` dit à la fois "est-ce une String ?" et "si oui, mets-la dans s". Deux actions, une seule écriture.

La variable `s` n'est accessible que dans le bloc du `if`. On appelle ça **flow scoping** (portée liée au flux). Le compilateur sait exactement où `s` est valide, et il vous le rappellera si vous essayez de l'utiliser ailleurs !

```java
public static void process(Object obj) {
  if (obj instanceof String s) {
    IO.println("String de longueur " + s.length());
  } else if (obj instanceof Integer i) {
    IO.println("Entier : " + (i * 2));
  } else if (obj instanceof List<?> list) {
    IO.println("Liste de taille " + list.size());
  } else {
    IO.println("Type inconnu");
  }
}
```

Une chaîne d'`else if` devenue limpide : chaque cas teste un type et donne directement accès à la variable typée. Fini les `(String) obj`, `(Integer) obj` qui encombrent la lecture !

### Conditions combinées

```java
if (obj instanceof String s && s.length() > 5) {
  IO.println("String long : " + s);
}
```

Avec `&&`, la condition de droite n'est évaluée que si `s` est bien définie. Élégant et sûr.

Mais attention, le `||` ne fonctionne pas (car `s` pourrait ne pas être défini) :

```java
// if (obj instanceof String s || s.length() > 5) { } // erreur de compilation
```

Logique : avec `||`, si le premier test échoue, `s` n'existe pas encore, donc impossible de l'utiliser dans le second. Le compilateur vous protège de cette erreur subtile !

## Pattern matching dans switch

Combiné avec les [[11. if, switch-case|switch]], le pattern matching devient très puissant (Java 17+ en preview, Java 21+ stable).

```java
public static String describe(Object obj) {
  return switch (obj) {
    case String s -> "String: " + s;
    case Integer i -> "Entier: " + i;
    case Long l -> "Long: " + l;
    case null -> "C'est null !";
    default -> "Je ne sais pas quoi faire de ça";
  };
}
```

Chaque `case` teste un type et fournit la variable typée directement. Et remarquez le `case null` : on peut enfin gérer `null` proprement dans un switch !

### Gardes (when)

On peut ajouter des conditions supplémentaires avec `when` :

```java
public static String describe(Object obj) {
  return switch (obj) {
    case String s when s.length() > 10 -> "Long string: " + s;
    case String s -> "String court: " + s;
    case Integer i when i < 0 -> "Entier négatif";
    case Integer i -> "Entier positif ou nul";
    case null -> "null";
    default -> "Inconnu";
  };
}
```

Les gardes `when` permettent d'affiner un cas : d'abord "les Strings longues", puis "les autres Strings". On peut même avoir deux `case String s` différents, tant que les gardes ne se chevauchent pas !

### Combinaison avec sealed

Le pattern matching est particulièrement puissant avec les [[18. Les objets (Partie 2)#`sealed` (classes scellées)|classes sealed]] :

```java
public sealed interface Shape permits Circle, Rectangle, Triangle { }

public record Circle(double radius) implements Shape { }
public record Rectangle(double width, double height) implements Shape { }
public record Triangle(double base, double height) implements Shape { }

public double area(Shape shape) {
  return switch (shape) {
    case Circle c -> Math.PI * c.radius() * c.radius();
    case Rectangle r -> r.width() * r.height();
    case Triangle t -> t.base() * t.height() / 2;
    // pas besoin de default : toutes les formes sont couvertes !
  };
}
```

Le duo sealed + pattern matching est magique : le compilateur **sait** que `Circle`, `Rectangle` et `Triangle` sont les seules implémentations possibles. Il n'y a donc pas besoin de `default`, et si quelqu'un ajoute une forme, le compilateur vous forcera à la traiter. L'exhaustivité est garantie !

### Records et destructuration

Avec les [[24. Les records|records]], on peut destructurer directement dans le pattern :

```java
public record Point(int x, int y) { }
public record Line(Point start, Point end) { }

public static String describe(Object obj) {
  return switch (obj) {
    case Point(int x, int y) -> "Point en (" + x + ", " + y + ")";
    case Line(Point(int x1, int y1), Point(int x2, int y2)) ->
        "Ligne de (" + x1 + "," + y1 + ") vers (" + x2 + "," + y2 + ")";
    default -> "Autre";
  };
}
```

La destructuration extrait les composants directement dans les variables : `Point(int x, int y)` donne accès à `x` et `y` en une fois. Et elle se compose : `Line(Point(...), Point(...))` extrait même les coordonnées imbriquées d'une ligne !

### Null dans les switch

Avant Java 17, un `switch` sur `null` levait une `NullPointerException`. Avec le pattern matching, on peut gérer `null` directement :

```java
String value = null;
String result = switch (value) {
  case String s -> "C'est une string";
  case null -> "C'est null";
  default -> "Autre";
};
```

## Exemple complet

Allez, un exemple qui réunit tout ce qu'on a vu :

```java
sealed interface Animal permits Dog, Cat, Bird { }
record Dog(String name, String breed) implements Animal { }
record Cat(String name, boolean isIndoor) implements Animal { }
record Bird(String name, double wingspan) implements Animal { }

public String describeAnimal(Animal a) {
  return switch (a) {
    case Dog(String name, String breed) ->
        "Chien " + breed + " nommé " + name;
    case Cat(String name, boolean isIndoor) ->
        "Chat " + name + " (" + (isIndoor ? "intérieur" : "extérieur") + ")";
    case Bird(String name, double w) when w > 1.0 ->
        "Grand oiseau : " + name;
    case Bird(String name, double _) ->
        "Petit oiseau : " + name;
  };
}
```

Chaque animal est décrit avec son type, ses données destructurées, et même une garde pour différencier les grands oiseaux des petits. Tout ça sans un seul cast, sans une seule ligne de `instanceof` explicite !

## Pourquoi c'est utile ?

- **Plus de cast manuels** : `if (x instanceof Foo) { Foo f = (Foo) x; ... }` → `if (x instanceof Foo f) { ... }`
- **Plus sûr** : le compilateur vérifie que le cast est valide
- **Plus concis** : moins de code pour le même résultat
- **Exhaustivité** : avec `sealed`, le compilateur vérifie que tous les cas sont traités

Le pattern matching est une de ces fonctionnalités qu'on adore dès qu'on y a goûté : moins de code, plus de sécurité, et un compilateur qui veille sur nous. On continue avec [[34. Librairies et frameworks|les librairies et frameworks]] !
