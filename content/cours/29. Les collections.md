Bon, les [[15. Les tableaux|tableaux]] c'est bien gentil, mais ça a ses limites. Tailles fixes, pas de tri intégré, pas de recherche rapide... Il nous fallait quelque chose de plus costaud !

Les **collections** sont des classes du JDK qui permettent de stocker des éléments. Un peu comme les tableaux, mais bien plus flexibles. On trouve par exemple :

- `List`
- `Set`
- `Map`
- `Queue`
- `Deque`

On va détailler les trois premières bien comme il faut. Les deux autres sont moins fréquentes au début.

> [!info]
> Les collections utilisent les [[27. Les génériques|génériques]] avec la syntaxe `<>`. Si ce n'est pas clair, jetez un œil au chapitre dédié !

## List

Les listes sont des collections **ordonnées** qui peuvent contenir des **doublons**. C'est ce qui se rapproche le plus d'un tableau, en version bien plus malléable.

```java
List<String> names = new ArrayList<>();
```

### Ajouter des éléments

```java
names.add("Alice");     // ajoute à la fin
names.add("Bob");
names.add("Charlie");
names.add(1, "David");  // insère à l'index 1 (entre Alice et Bob)
```

### Accéder aux éléments

```java
String first = names.get(0);    // "Alice"
String second = names.get(1);   // "David"
int size = names.size();        // 4
```

### Modifier et supprimer

```java
names.set(0, "Eve");            // remplace l'index 0
names.remove(2);                // supprime l'index 2
names.remove("Bob");            // supprime l'objet "Bob"
names.clear();                  // vide la liste
```

### Parcourir une liste

```java
// Boucle for classique
for (int i = 0; i < names.size(); i++) {
  IO.println(names.get(i));
}

// Boucle for-each
for (String name : names) {
  IO.println(name);
}

// Avec une lambda (Java 8+)
names.forEach(name -> IO.println(name));
names.forEach(IO::println);
```

Trois façons de faire la même chose. La boucle `for` classique quand on a besoin de l'index, la `for-each` pour la simplicité, et les lambdas (on verra ça dans [[31. La programmation fonctionnelle]]) pour l'élégance !

### ArrayList vs LinkedList

```java
List<String> arrayList = new ArrayList<>();  // rapide pour accès par index
List<String> linkedList = new LinkedList<>(); // rapide pour ajout/suppression au début
```

- `ArrayList` : tableau redimensionnable → accès rapide, insertion lente au milieu
- `LinkedList` : liste chaînée → accès lent, insertion rapide aux extrémités

En pratique, `ArrayList` est utilisé 95% du temps. C'est la valeur sûre : simple, rapide, fiable !

## Set

Les `Set` sont des collections qui **ne contiennent pas de doublons**. L'ordre n'est pas garanti. Autrement dit : chaque élément unique, un point c'est tout !

```java
Set<String> names = new HashSet<>();
names.add("Alice");
names.add("Bob");
names.add("Alice");   // ignoré, déjà présent
IO.println(names.size()); // 2, pas 3
```

Remarquez le travail de `equals()` et `hashCode()` que vous connaissez déjà (chapitre [[21. equals et hashCode]]). C'est grâce à eux que le `Set` détecte les doublons — encore une bonne raison de les redéfinir proprement !

### Test de présence

```java
if (names.contains("Alice")) {
  IO.println("Alice est dans le set");
}
```

C'est la grande force du `Set` : `contains()` est **très rapide**, contrairement à une `List` où il faut parcourir tous les éléments. Un `contains` sur une `List` de 10 000 éléments, c'est jusqu'à 10 000 comparaisons ; sur un `HashSet`, c'est quasi instantané !

### Parcourir un Set

```java
for (String name : names) {
  IO.println(name);
}
```

### HashSet vs TreeSet

```java
Set<String> hashSet = new HashSet<>();    // plus rapide, ordre quelconque
Set<String> treeSet = new TreeSet<>();    // plus lent, mais trié
```

Besoin d'un ordre précis ? `TreeSet`, qui trie au fur et à mesure. Juste l'unicité ? `HashSet`, le champion de la vitesse. Le choix se résume à : est-ce que je veux du trié, oui ou non ?

## Map

Les `Map` sont des collections qui associent des **clés** à des **valeurs**. Comme un dictionnaire : à chaque mot (clé) correspond une définition (valeur).

```java
Map<String, Integer> ages = new HashMap<>();
```

### Ajouter des entrées

```java
ages.put("Alice", 25);
ages.put("Bob", 30);
ages.put("Charlie", 35);
ages.put("Alice", 26);  // remplace l'ancienne valeur (25 → 26)
```

Chaque clé est unique : si on remet une clé existante, la valeur est simplement remplacée. Pas de doublon possible côté clés !

### Accéder aux valeurs

```java
int age = ages.get("Alice");        // 26
int unknown = ages.getOrDefault("David", 0); // 0 si pas trouvé
boolean exists = ages.containsKey("Bob");   // true
boolean hasValue = ages.containsValue(30);  // true
```

`getOrDefault` est votre allié pour éviter les `null` surprises quand une clé n'existe pas. On demande une valeur, et si elle manque, on reçoit un joli remplaçant par défaut !

### Parcourir une Map

```java
// Parcourir les entrées
for (Map.Entry<String, Integer> entry : ages.entrySet()) {
  IO.println(entry.getKey() + " a " + entry.getValue() + " ans");
}

// Parcourir les clés
for (String name : ages.keySet()) {
  IO.println(name);
}

// Parcourir les valeurs
for (int age : ages.values()) {
  IO.println(age);
}
```

La boucle sur `entrySet()` est la plus utilisée : elle donne accès à la paire clé/valeur d'un coup. Le trio gagnant !

### HashMap vs TreeMap

```java
Map<String, Integer> hashMap = new HashMap<>();  // rapide, ordre quelconque
Map<String, Integer> treeMap = new TreeMap<>();  // lent, clés triées
```

Même logique que pour les sets : `HashMap` pour la vitesse, `TreeMap` si on veut des clés triées.

## Queue et Deque

### Queue

Une `Queue` (file d'attente) fonctionne en **FIFO** (First In, First Out) : le premier arrivé est le premier servi. Exactement comme dans un vrai commerce !

```java
Queue<String> queue = new LinkedList<>();
queue.offer("Alice");   // ajoute à la fin
queue.offer("Bob");
queue.offer("Charlie");

String first = queue.poll();  // retire et retourne le premier ("Alice")
String next = queue.peek();   // regarde le premier sans le retirer ("Bob")
```

`offer` fait entrer, `poll` fait sortir, `peek` jette un œil sans rien bouger. L'ordre est respecté à la lettre : le premier servi, c'est bien le premier arrivé !

### Deque

Une `Deque` (Double Ended Queue) peut fonctionner aux deux extrémités :

```java
Deque<String> stack = new ArrayDeque<>();
stack.push("Alice");   // ajoute au début
stack.push("Bob");
stack.push("Charlie");

String top = stack.pop();  // retire et retourne le dernier ajouté ("Charlie")
// Comportement LIFO (pile) ! pratique pour une stack
```

`push` et `pop` : c'est le comportement LIFO d'une pile (Last In, First Out). Le dernier ajouté est le premier retiré — comme une pile d'assiettes !

## Tableau comparatif

| Collection | Ordonné ? | Doublons ? | Accès par index ? | Vitesse |
|:---|:---|:---|:---|:---|
| `ArrayList` | Oui | Oui | Oui (`get(i)`) | Très rapide |
| `LinkedList` | Oui | Oui | Oui (mais lent) | Rapide extrémités |
| `HashSet` | Non | Non | Non | Très rapide |
| `TreeSet` | Trié | Non | Non | Moins rapide |
| `HashMap` | Non | Non (clés) | Par clé | Très rapide |
| `TreeMap` | Trié (clés) | Non (clés) | Par clé | Moins rapide |

> [!tip]
> Si vous hésitez, commencez par `ArrayList`, `HashSet` et `HashMap`. Ce sont les plus utilisés et ils couvrent 90% des besoins.

Les collections sont un outil de tous les jours : on les croise dans à peu près tous les programmes Java. Savoir choisir la bonne au bon moment, c'est un réflexe qui viendra vite. Et une fois qu'on maîtrise les bases, on peut les rendre encore plus expressives avec les [[31. La programmation fonctionnelle|lambdas et les méthodes de programmation fonctionnelle]] !
