Quand un programme rencontre une situation anormale (fichier introuvable, division par zéro, saisie invalide…), il peut **planter** ou… **gérer l'erreur** proprement. C'est le rôle des **exceptions**. Et croyez-moi, savoir les maîtriser, c'est ce qui sépare un programme fragile d'un programme solide !

## Qu'est-ce qu'une exception ?

Une exception est un événement qui interrompt le déroulement normal d'un programme. Il se passe quelque chose d'imprévu, et le programme réagit.

```java
void main() {
  int result = 10 / 0; // ArithmeticException !
  IO.println("Ceci ne sera jamais exécuté");
}
```

Quand l'exception est levée, le programme s'arrête et affiche une **stack trace** qui permet de comprendre où et pourquoi l'erreur s'est produite. C'est le fameux message d'erreur rouge qu'on a tous déjà vu (et qu'on apprend à aimer, car il nous dit exactement quoi réparer !).

## try / catch

Pour gérer une exception, on encadre le code dangereux dans un bloc `try` et on attrape l'exception avec `catch` :

```java
void main() {
  try {
    int result = 10 / 0;
    IO.println("Ceci ne sera pas affiché");
  } catch (ArithmeticException e) {
    IO.println("Erreur : division par zéro !");
  }

  IO.println("Le programme continue !");
}
```

Regardez bien : grâce au `catch`, le programme ne s'écroule pas, il affiche un message propre et **continue**. C'est tout l'intérêt : on maîtrise l'erreur au lieu de la subir.

### Attraper plusieurs exceptions

Un `try` peut être suivi de plusieurs `catch`, un pour chaque type d'exception à gérer :

```java
void main() {
  try {
    String s = null;
    IO.println(s.length()); // NullPointerException
    int[] array = new int[3];
    IO.println(array[10]);   // ArrayIndexOutOfBoundsException (jamais atteint)
  } catch (NullPointerException e) {
    IO.println("Référence null détectée");
  } catch (ArrayIndexOutOfBoundsException e) {
    IO.println("Index hors limites");
  }
}
```

Depuis Java 7, on peut attraper plusieurs exceptions d'un coup, si on veut leur réserver le même traitement :

```java
try {
  // code dangereux
} catch (NullPointerException | ArrayIndexOutOfBoundsException e) {
  IO.println("Problème de référence ou d'index");
}
```

## finally

Le bloc `finally` est exécuté **quoi qu'il arrive** (exception ou non). Idéal pour libérer des ressources.

```java
void main() {
  try {
    IO.println("Tentative périlleuse…");
    throw new RuntimeException("Oups !");
  } catch (RuntimeException e) {
    IO.println("Exception attrapée");
  } finally {
    IO.println("finally : exécuté TOUT LE TEMPS");
  }
}
```

Même avec un `return` dans le `try`, le `finally` s'exécute avant que la méthode ne se termine. C'est le bloc de confiance : il passe toujours, sans exception (sans mauvais jeu de mots) !

## Checked vs Unchecked

En Java, il y a deux catégories d'exceptions. Cette distinction est importante, elle influence directement la façon dont vous écrivez votre code.

### Unchecked exceptions (RuntimeException)

Héritent de `RuntimeException`. Le compilateur **n'oblige pas** à les gérer. Ce sont des erreurs de programmation (bugs) :
- `ArithmeticException` (division par zéro)
- `NullPointerException` (appel sur null)
- `ArrayIndexOutOfBoundsException` (index invalide)
- `IllegalArgumentException` (argument invalide)

```java
public void setAge(int age) {
  if (age < 0) {
    throw new IllegalArgumentException("L'âge ne peut pas être négatif");
  }
  this.age = age;
}
```

### Checked exceptions

Héritent de `Exception` (mais pas de `RuntimeException`). Le compilateur **oblige** à les gérer (try/catch ou throws) :
- `IOException` (erreur de lecture/écriture)
- `FileNotFoundException` (fichier introuvable)
- `SQLException` (erreur de base de données)

```java
void readFile(String path) {
  // Erreur de compilation : FileNotFoundException est checked !
  FileReader reader = new FileReader(path);
}
```

Il faut soit entourer d'un try/catch :

```java
void readFile(String path) {
  try {
    FileReader reader = new FileReader(path);
    IO.println("Fichier ouvert");
  } catch (FileNotFoundException e) {
    IO.println("Fichier introuvable : " + path);
  }
}
```

Soit déclarer que la méthode peut lancer l'exception avec **throws** :

```java
void readFile(String path) throws FileNotFoundException {
  FileReader reader = new FileReader(path);
}
```

## throws

Le mot clé `throws` dans la signature d'une méthode indique que cette méthode peut lancer une exception sans la gérer. C'est à l'appelant de s'en occuper.

```java
void main() throws FileNotFoundException {
  readFile("data.txt"); // je laisse passer, c'est le main qui gérera
}

void readFile(String path) throws FileNotFoundException {
  FileReader reader = new FileReader(path);
}
```

En pratique, on ne met pas `throws` sur le `main` (sauf pour les programmes simples), car c'est repousser le problème. Mieux vaut gérer l'exception là où on a le contexte pour le faire.

## try-with-resources

Depuis Java 7, si une ressource implémente `AutoCloseable`, on peut l'ouvrir dans un `try` et elle sera fermée automatiquement. Comparez ces deux versions, c'est parlant :

```java
// Avant
BufferedReader reader = null;
try {
  reader = new BufferedReader(new FileReader("file.txt"));
  IO.println(reader.readLine());
} catch (IOException e) {
  IO.println("Erreur de lecture");
} finally {
  if (reader != null) reader.close();
}

// Après — try-with-resources
try (BufferedReader reader = new BufferedReader(new FileReader("file.txt"))) {
  IO.println(reader.readLine());
} catch (IOException e) {
  IO.println("Erreur de lecture");
}
```

Plus besoin du `finally` pour fermer ! La ressource est automatiquement fermée à la fin du `try`. Moins de code, moins de risques d'oubli : on adore.

## Créer ses propres exceptions

On peut définir des exceptions personnalisées en étendant `Exception` (checked) ou `RuntimeException` (unchecked) :

```java
public class InsufficientBalanceException extends RuntimeException {
  public InsufficientBalanceException(double balance, double amount) {
    super("Solde insuffisant : " + balance + "€, besoin de " + amount + "€");
  }
}

public class BankAccount {
  private double balance;

  public void withdraw(double amount) {
    if (amount > balance) {
      throw new InsufficientBalanceException(balance, amount);
    }
    balance -= amount;
  }
}
```

Créer sa propre exception, c'est donner un nom et un message clair à une situation précise de votre domaine. Vos collègues (et vous) comprendront immédiatement ce qui s'est passé.

## Bonnes pratiques

1. **Ne pas attraper `Exception` ou `Throwable`** trop largement — attrapez des exceptions spécifiques
2. **Ne pas ignorer les exceptions** — un `catch` vide cache les problèmes
3. **Utiliser les exceptions pour les cas exceptionnels** — pas pour le contrôle de flux normal
4. **Préférer les unchecked** pour les erreurs de programmation, les checked pour les erreurs récupérables

```java
// À ÉVITER
try {
  // code
} catch (Exception e) {
  // rien — on ignore l'erreur, très mauvaise pratique
}

// BON
try {
  // code
} catch (FileNotFoundException e) {
  IO.println("Fichier introuvable, utilisation des valeurs par défaut");
}
```

Les exceptions sont un mécanisme puissant pour écrire du code robuste. Bien utilisées, elles rendent vos programmes **prévisibles** même en cas d'erreur. Et mal utilisées, elles transforment un bug en mystère silencieux. Vous savez désormais quoi faire !
