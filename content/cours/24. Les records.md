Les **records** (introduits dans Java 14 en preview, finalisés dans Java 16) sont une façon très concise de déclarer des classes dont le but principal est de **porter des données**. Et croyez-moi, quand vous aurez goûté aux records, vous ne voudrez plus jamais écrire une classe "data" à la main !

## Le problème

Regardez tout le code qu'on a écrit pour notre classe `Person` dans [[16. Les objets (Partie 1)]] :

```java
public class Person {
  private final String firstName;
  private final String lastName;
  private final int age;

  public Person(String firstName, String lastName, int age) {
    this.firstName = firstName;
    this.lastName = lastName;
    this.age = age;
  }

  public String getFirstName() { return firstName; }
  public String getLastName() { return lastName; }
  public int getAge() { return age; }

  @Override
  public boolean equals(Object obj) { ... }

  @Override
  public int hashCode() { ... }

  @Override
  public String toString() { return "Person[firstName=" + firstName + ", lastName=" + lastName + ", age=" + age + "]"; }
}
```

C'est beaucoup de code pour une simple classe qui ne fait que contenir des données. Et tout ça, c'est du **boilerplate** : du code répétitif qu'on écrit sans réfléchir, juste pour satisfaire les conventions. Un **record** permet d'écrire tout ça en une seule ligne :

```java
public record Person(String firstName, String lastName, int age) { }
```

C'est tout. Vraiment. Une ligne pour remplacer tout le bloc précédent. Impressionnant, non ?

## Ce qu'un record génère automatiquement

Avec cette déclaration, le compilateur crée automatiquement :

- Les **attributs** `private final` pour chaque champ
- Un **constructeur** avec tous les paramètres
- Des **accesseurs** (méthodes d'accès) — par exemple `firstName()` et pas `getFirstName()`
- `equals()` et `hashCode()` basés sur tous les champs
- `toString()` qui affiche tous les champs

```java
void main() {
  Person p = new Person("Alice", "Dupont", 30);
  IO.println(p.firstName()); // Alice — pas getFirstName() !
  IO.println(p.lastName());  // Dupont
  IO.println(p.age());       // 30
  IO.println(p);             // Person[firstName=Alice, lastName=Dupont, age=30]
}
```

Notez au passage les accesseurs sans `get` : `p.firstName()`, pas `p.getFirstName()`. C'est la convention des records, et elle est plus courte !

## Records et immutabilité

Les records sont **implicitement immutables** : tous leurs champs sont `final`. Une fois créé, un record ne peut pas être modifié.

```java
Person p = new Person("Alice", "Dupont", 30);
// p.firstName = "Bob";        // erreur : les attributs sont finals
// p.setFirstName("Bob");      // erreur : pas de setter
```

Pour "modifier" un record, il faut en créer un nouveau :

```java
Person older = new Person(p.firstName(), p.lastName(), p.age() + 1);
```

Pas de setter, pas de modification : si on veut une valeur différente, on fabrique une nouvelle instance. C'est simple, prévisible, et on retrouvera ce goût pour l'[[30. Mutable et Immuable|immuabilité]] très bientôt !

## Constructeur compact

On peut ajouter de la validation dans un record avec un **constructeur compact** :

```java
public record Person(String firstName, String lastName, int age) {
  public Person {
    if (age < 0) {
      throw new IllegalArgumentException("L'âge ne peut pas être négatif : " + age);
    }
    if (firstName == null || lastName == null) {
      throw new NullPointerException("Les noms ne peuvent pas être null");
    }
  }
}
```

Pas besoin de réécrire les assignations `this.firstName = firstName`, le compilateur les ajoute automatiquement après le constructeur compact. On ne s'occupe que de la partie intéressante : les règles de validation !

## Ajouter des méthodes

On peut ajouter des méthodes personnalisées à un record :

```java
public record Person(String firstName, String lastName, int age) {
  public String fullName() {
    return firstName + " " + lastName;
  }

  public boolean isAdult() {
    return age >= 18;
  }
}
```

```java
void main() {
  Person p = new Person("Alice", "Dupont", 30);
  IO.println(p.fullName()); // Alice Dupont
  IO.println(p.isAdult());  // true
}
```

Un record n'est pas qu'une coquille vide : il peut porter de la logique métier, tant que ses données de base restent immuables.

## Restrictions des records

Les records ne peuvent pas :
- étendre une autre classe (ils étendent **implicitement** `java.lang.Record`)
- avoir des attributs non-`static` supplémentaires (seuls ceux déclarés dans la signature comptent)
- être `abstract`

Mais ils peuvent :
- implémenter des [[23. Les interfaces|interfaces]]
- avoir des attributs et méthodes `static`
- avoir des méthodes personnalisées

```java
public record Person(String firstName, String lastName, int age) implements Comparable<Person> {
  public static final int ADULT_AGE = 18;

  @Override
  public int compareTo(Person other) {
    return Integer.compare(this.age, other.age);
  }
}
```

On retrouve nos interfaces de tout à l'heure : un record peut très bien signer un contrat !

## Quand utiliser un record ?

Un record est parfait quand votre classe est essentiellement un **ensemble de données** (un "value object" ou "data carrier"). C'est le cas pour :
- des DTO (Data Transfer Objects)
- des paires clé/valeur
- des résultats de méthodes
- des données immutables

```java
public record Point(int x, int y) { }
public record Address(String street, String city, String zipCode) { }
public record Product(String name, double price, int quantity) { }
```

Avant les records, on utilisait des classes avec beaucoup de boilerplate (ou des librairies comme Lombok). Les records simplifient tout ça **directement dans le langage**. Plus besoin de dépendance externe pour avoir des données propres et immuables !

Une dernière précision pour la route : les records ne remplacent pas toutes les classes. Si votre classe a une vraie identité (elle change d'état, elle a des comportements qui la modifient), une classe classique reste le bon choix. Le record, c'est pour porter des données, et c'est déjà énorme !
