Parfois, une classe n'a de sens qu'à l'intérieur d'une autre classe. C'est le moment d'utiliser une **classe interne** (inner class) : une classe déclarée à l'intérieur d'une autre classe. C'est un peu comme ranger ses outils dans des tiroirs bien organisés plutôt que de tout laisser traîner sur l'établi !

## Classe interne simple

```java
public class Bank {
  private String name;

  public Bank(String name) {
    this.name = name;
  }

  public class Account {
    private String accountNumber;
    private double balance;

    public Account(String accountNumber) {
      this.accountNumber = accountNumber;
      this.balance = 0;
    }

    public void deposit(double amount) {
      balance += amount;
      IO.println("Dépôt de " + amount + "€ sur le compte " + accountNumber + " (" + name + ")");
    }

    public void display() {
      IO.println("Compte " + accountNumber + " à la " + name + " : " + balance + "€");
    }
  }
}
```

Ici, un compte n'a de sens que dans une banque, et la classe `Account` est rangée dans `Bank`. Logique, non ? Notez que `Account` utilise `name` — un attribut `private` de `Bank`. Les classes internes ont accès à tous les membres de la classe englobante, même les `private`. C'est le grand avantage !

Pour créer une instance de `Account`, on a besoin d'une instance de `Bank` :

```java
void main() {
  Bank bank = new Bank("Crédit Mutuelex");
  Bank.Account account = bank.new Account("FR123456");
  account.deposit(1000);
  account.display();
}
```

Regardez la syntaxe : `bank.new Account(...)`. On crée le compte "dans" la banque, d'où cette façon d'écrire. Un peu inhabituel au début, mais on s'y habitue vite !

## Classe interne statique (static nested class)

Si la classe interne n'a pas besoin d'accéder aux membres de l'instance englobante, on peut la déclarer `static`.

```java
public class MathUtils {
  public static class Pair {
    private int a;
    private int b;

    public Pair(int a, int b) {
      this.a = a;
      this.b = b;
    }

    public int sum() {
      return a + b;
    }
  }
}
```

Avantage : on n'a pas besoin d'une instance de `MathUtils` pour créer un `Pair` :

```java
void main() {
  MathUtils.Pair p = new MathUtils.Pair(3, 4);
  IO.println(p.sum()); // 7
}
```

C'est comme une classe normale, mais rangée dans une autre classe pour l'organisation. Pas de dépendance à une instance de l'extérieur !

### Différence

| Classe interne (non static) | Classe interne statique |
|:---|:---|
| A besoin d'une instance de la classe englobante | N'en a pas besoin |
| Peut accéder aux membres de l'instance englobante | Ne peut pas (sauf membres `static`) |
| `outerInstance.new Inner()` | `new Outer.Inner()` |

Le choix est simple : s'il vous faut les membres de l'instance englobante → classe interne ; sinon → classe statique, plus légère.

## Classe locale

On peut aussi déclarer une classe à l'intérieur d'une méthode :

```java
void main() {
  class Point {
    int x;
    int y;

    Point(int x, int y) {
      this.x = x;
      this.y = y;
    }

    int distance() {
      return x + y; // version simplifiée
    }
  }

  Point p = new Point(3, 4);
  IO.println(p.distance());
}
```

La classe locale n'est visible que dans la méthode où elle est déclarée. C'est un outil pratique pour structurer un algorithme sans polluer le reste du code. Elle vit sa vie dans la méthode, et disparaît avec elle !

## Classe anonyme

Une classe anonyme est une classe sans nom, déclarée et instanciée en même temps. Utile pour implémenter une interface ou étendre une classe à la volée.

```java
interface SayHello {
  void greet();
}

void main() {
  SayHello french = new SayHello() {
    @Override
    public void greet() {
      IO.println("Bonjour !");
    }
  };

  SayHello english = new SayHello() {
    @Override
    public void greet() {
      IO.println("Hello!");
    }
  };

  french.greet();
  english.greet();
}
```

Pas de nom de classe : on déclare directement l'implémentation de `SayHello` au moment de l'instanciation. Pratique quand on a besoin d'un objet qui fait une petite chose précise, une seule fois.

Les classes anonymes sont souvent remplacées par les [[31. La programmation fonctionnelle|lambdas]] aujourd'hui, mais vous les rencontrerez encore dans du code plus ancien.

```java
// Avec une lambda (Java 8+)
SayHello french = () -> IO.println("Bonjour !");
```

Beaucoup plus court, non ? La lambda fait le même travail en une ligne. Mais pour comprendre les lambdas, il faut d'abord savoir ce qu'elles remplacent — c'est exactement pourquoi on regarde les classes anonymes maintenant !

## À quoi servent les classes internes ?

- **Organisation** : regrouper des classes qui vont logiquement ensemble
- **Encapsulation renforcée** : cacher des détails d'implémentation
- **Lisibilité** : le code est au bon endroit

Le JDK en utilise partout. Par exemple, `HashMap` a une classe interne `Node` pour représenter ses entrées, et `ArrayList` a une classe interne `Itr` pour son itérateur. Quand vous utilisez une collection, c'est toute une armée de classes internes qui travaille dans l'ombre pour vous !
