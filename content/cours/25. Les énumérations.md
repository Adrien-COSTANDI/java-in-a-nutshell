Une **énumération** (`enum`) est un type qui permet de définir un ensemble fixe de constantes nommées. C'est un concept simple en apparence, mais terriblement pratique. Allez, on découvre ça ensemble !

```java
public enum Day {
  MONDAY, TUESDAY, WEDNESDAY, THURSDAY, FRIDAY, SATURDAY, SUNDAY
}
```

Voilà, on vient de créer un type `Day` qui ne peut prendre que 7 valeurs : les jours de la semaine. Fini les erreurs de frappe, le compilateur veille !

## Pourquoi pas des constantes ?

Vous vous dites peut-être : "mais je peux faire ça avec des constantes, non ?" Regardez ce que ça donne sans `enum` :

```java
public static final int MONDAY = 0;
public static final int TUESDAY = 1;
// ...
void setAlarm(int day) {
  if (day == MONDAY || day == TUESDAY) { }
}
setAlarm(99); // pas de sécurité : 99 est un jour invalide mais le compilateur accepte
```

Le problème saute aux yeux : rien n'empêche de passer `99` à la méthode. Le compilateur accepte n'importe quel `int`, et votre programme se retrouve avec un "jour" qui n'existe pas. Avec un `enum` :

```java
void setAlarm(Day day) {
  // day ne peut être que MONDAY, TUESDAY, ..., SUNDAY
  // impossible de passer autre chose !
}
setAlarm(Day.MONDAY); // ok
// setAlarm(99);      // erreur de compilation
```

La sécurité vient du compilateur lui-même : il est impossible de lui faire avaler une valeur qui n'est pas dans la liste. C'est exactement ce qu'on veut !

## Utilisation de base

```java
Day today = Day.WEDNESDAY;

IO.println(today);          // WEDNESDAY

// Toutes les valeurs
for (Day d : Day.values()) {
  IO.println(d);
}

// Nom et position
IO.println(today.name());    // "WEDNESDAY"
IO.println(today.ordinal()); // 2 (position, à partir de 0)
```

`values()` renvoie toutes les constantes, `name()` donne le nom en texte, `ordinal()` donne la position. Vous avez tous les outils pour jouer avec votre énumération !

## switch avec enum

Les `enum` se marient à merveille avec les `switch` (souvenez-vous, on a appris ça au [[11. if, switch-case|chapitre des conditions]]) :

```java
Day today = Day.WEDNESDAY;

switch (today) {
  case MONDAY -> IO.println("Lundi, ça repart");
  case FRIDAY -> IO.println("Vendredi !");
  case SATURDAY, SUNDAY -> IO.println("Week-end !");
  default -> IO.println("Jour de semaine");
}
```

Avec un `enum`, plus de constantes magiques à retenir : chaque cas est explicite, lisible, et le compilateur vérifie que vos valeurs existent vraiment.

## Enum avec des champs et méthodes

Et là, ça devient amusant : un `enum` peut avoir des attributs, un constructeur et des méthodes. C'est une classe à part entière ! Regardez cet exemple célèbre du tutoriel Java d'Oracle, adapté ici :

```java
public enum Planet {
  MERCURY(3.303e23, 2.4397e6),
  VENUS(4.869e24, 6.0518e6),
  EARTH(5.976e24, 6.37814e6),
  MARS(6.421e23, 3.3972e6),
  JUPITER(1.9e27, 7.1492e7),
  SATURN(5.688e26, 6.0268e7),
  URANUS(8.686e25, 2.5559e7),
  NEPTUNE(1.024e26, 2.4746e7);

  private final double mass;    // en kg
  private final double radius;  // en mètres

  Planet(double mass, double radius) {
    this.mass = mass;
    this.radius = radius;
  }

  public double getMass() { return mass; }
  public double getRadius() { return radius; }

  // Gravité à la surface
  public double surfaceGravity() {
    return 6.67430e-11 * mass / (radius * radius);
  }
}
```

```java
void main() {
  for (Planet p : Planet.values()) {
    IO.println(p + " : gravité = " + p.surfaceGravity());
  }
}
```

Chaque constante est créée avec ses propres valeurs : Mercure avec sa masse et son rayon, Terre avec les siens... et chaque planète sait calculer sa gravité de surface. Un seul type, 8 objets bien rangés, chacun avec ses données et ses comportements !

## Méthodes spécifiques par constante

On peut même aller plus loin : chaque constante peut avoir son propre comportement !

```java
public enum Operation {
  PLUS { public double apply(double a, double b) { return a + b; } },
  MINUS { public double apply(double a, double b) { return a - b; } },
  TIMES { public double apply(double a, double b) { return a * b; } },
  DIVIDE { public double apply(double a, double b) { return a / b; } };

  public abstract double apply(double a, double b);
}
```

```java
void main() {
  double a = 10;
  double b = 3;

  for (Operation op : Operation.values()) {
    IO.println(a + " " + op + " " + b + " = " + op.apply(a, b));
  }
}
```

Chaque constante définit sa propre version de `apply`. C'est puissant, et ça évite un énorme `switch` sur des valeurs arbitraires.

## EnumSet et EnumMap

Bonus : il existe des collections spécialisées pour les `enum`, très performantes. On les verra en détail dans [[29. Les collections|le chapitre des collections]], mais voici un aperçu :

```java
import java.util.EnumSet;

EnumSet<Day> weekend = EnumSet.of(Day.SATURDAY, Day.SUNDAY);
EnumSet<Day> weekdays = EnumSet.range(Day.MONDAY, Day.FRIDAY);
EnumSet<Day> all = EnumSet.allOf(Day.class);

if (weekend.contains(today)) {
  IO.println("C'est le week-end !");
}
```

```java
import java.util.EnumMap;

EnumMap<Day, String> schedule = new EnumMap<>(Day.class);
schedule.put(Day.MONDAY, "Cours de Java");
schedule.put(Day.WEDNESDAY, "Sport");
schedule.put(Day.FRIDAY, "Cinéma");
```

On associe une valeur à chaque jour : simple, lisible et rapide.

## Enum vs Records

Les `enum` et les [[24. Les records|records]] sont deux outils pour des besoins différents. Petite comparaison pour bien les situer :

| `enum` | `record` |
|:---|:---|
| Ensemble **fixe** de constantes | Porteur de données |
| Peut avoir plusieurs instances (les constantes) | Une instance par valeur |
| Idéal pour des catégories limitées | Idéal pour des données immutables |

```java
// Enum : ensemble fini et connu à l'avance
public enum Season { SPRING, SUMMER, AUTUMN, WINTER }

// Record : on ne connaît pas les valeurs à l'avance
public record Person(String name, int age) { }
```

Le `enum` répond à la question "quelles sont toutes les valeurs possibles ?", le `record` à la question "quelles données dois-je transporter ?". Complémentaires, pas concurrents !

## Quand utiliser un enum ?

- États d'un système (`ACTIVE`, `INACTIVE`, `BANNED`)
- Rôles (`ADMIN`, `USER`, `MODERATOR`)
- Directions (`NORTH`, `SOUTH`, `EAST`, `WEST`)
- Types limités (`CIRCLE`, `RECTANGLE`, `TRIANGLE`)
- Constantes nommées qui ont un comportement associé

Les `enum` sont un outil élégant pour remplacer les constantes entières ou les `String` magiques. Ils apportent de la **sécurité** et de la **lisibilité** — deux qualités que tout programmeur qui se respecte recherche !
