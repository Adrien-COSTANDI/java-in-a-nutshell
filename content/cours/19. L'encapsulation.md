On a déjà parlé de [[18. Les objets (Partie 2)#Visibilité|visibilité]] avec `private` et `public`, mais l'**encapsulation** est un concept plus large. C'est l'idée de **cacher les détails internes** d'un objet et de **contrôler l'accès** à ses données. En clair : votre objet doit être une petite boîte bien fermée, où seul le nécessaire est accessible de l'extérieur.

## Le principe

L'encapsulation consiste à :
1. Rendre les attributs `private` (protégés)
2. Fournir des méthodes `public` pour y accéder ou les modifier

```java
public class Person {
  private String firstName;
  private String lastName;
  private int age;

  public Person(String firstName, String lastName, int age) {
    this.firstName = firstName;
    this.lastName = lastName;
    this.age = age;
  }

  public String getFirstName() {
    return firstName;
  }

  public void setFirstName(String firstName) {
    this.firstName = firstName;
  }

  public int getAge() {
    return age;
  }

  public void setAge(int age) {
    if (age < 0) {
      IO.println("L'âge ne peut pas être négatif !");
      return;
    }
    this.age = age;
  }
}
```

Sans encapsulation, n'importe qui pourrait faire `person.age = -5`, ce qui n'a aucun sens. Avec encapsulation, on **valide** les données avant de les modifier. C'est votre objet qui a le dernier mot sur ce qui rentre, pas le monde extérieur !

## Getters et Setters

Les méthodes `get…` et `set…` sont des conventions très répandues en Java (on appelle ça le **JavaBeans pattern**) :

- Un **getter** (`getNom`) retourne la valeur d'un attribut
- Un **setter** (`setNom`) modifie la valeur d'un attribut

```java
public class BankAccount {
  private double balance;

  public double getBalance() {
    return balance;
  }

  public void deposit(double amount) {
    if (amount <= 0) {
      IO.println("Le montant doit être positif !");
      return;
    }
    balance += amount;
  }

  public void withdraw(double amount) {
    if (amount <= 0) {
      IO.println("Le montant doit être positif !");
      return;
    }
    if (amount > balance) {
      IO.println("Solde insuffisant !");
      return;
    }
    balance -= amount;
  }
}
```

Remarquez ici qu'il n'y a **pas** de setter pour `balance`. On ne peut pas définir le solde arbitrairement ! On est obligé de passer par `deposit()` ou `withdraw()`, qui valident les opérations. C'est ça, l'encapsulation : on expose ce qui est nécessaire, on cache le reste.

## Pourquoi encapsuler ?

### 1. Validation des données

Le setter est le poste de contrôle de votre objet. C'est là qu'on refuse les valeurs absurdes :

```java
public void setAge(int age) {
  if (age < 0 || age > 150) {
    throw new IllegalArgumentException("Âge invalide : " + age);
  }
  this.age = age;
}
```

### 2. Flexibilité d'implémentation

Avec l'encapsulation, vous pouvez changer la façon dont les données sont stockées sans impacter les autres classes. C'est l'intérêt majeur : les autres classes ne savent **pas** comment vos données sont rangées, elles se contentent d'appeler vos méthodes publiques.

```java
// Avant
public class Person {
  private String firstName;
  private String lastName;

  public String getFullName() {
    return firstName + " " + lastName;
  }
}

// Après — les autres classes ne sont pas impactées !
public class Person {
  private String fullName;

  public String getFullName() {
    return fullName;
  }
}
```

La classe qui utilisait `getFullName()` n'a rien à changer : la façade publique est identique, seule l'intérieur a changé. C'est ça, la magie de l'encapsulation !

### 3. Contrôle d'accès

On peut décider qu'un attribut est **read-only** (pas de setter) ou **write-only** (pas de getter).

```java
public class User {
  private String username;
  private String password;

  public String getUsername() {
    return username;
  }
  // pas de setUsername — le nom d'utilisateur ne change pas

  public void setPassword(String password) {
    this.password = password;
  }
  // pas de getPassword — on ne divulgue pas le mot de passe !
}
```

Tout est une question de choix : vous décidez, attribut par attribut, ce que le monde extérieur a le droit de voir et de toucher.

## Encapsulation au niveau classe

L'encapsulation ne s'arrête pas aux attributs. On peut aussi encapsuler des **méthodes privées** qui ne sont que des outils internes :

```java
public class Calculator {

  public int computeComplexResult(int a, int b) {
    int intermediate1 = stepOne(a);
    int intermediate2 = stepTwo(b);
    return stepThree(intermediate1, intermediate2);
  }

  private int stepOne(int value) {
    return value * 3 + 2;
  }

  private int stepTwo(int value) {
    return value / 4 + 7;
  }

  private int stepThree(int a, int b) {
    return a + b - 3;
  }
}
```

L'extérieur ne voit que `computeComplexResult`. Les étapes intermédiaires sont cachées. Si on veut changer l'algorithme, on modifie les méthodes privées sans impacter le reste.

## Résumé

L'encapsulation c'est :
- attributs `private` par défaut
- getters/setters pour contrôler l'accès
- validation dans les setters
- méthodes internes `private` si elles ne sont pas nécessaires à l'extérieur
- **ne pas exposer plus que nécessaire**

C'est un pilier de la programmation orientée objet, au même titre que l'[[18. Les objets (Partie 2)#Héritage|héritage]]. Une fois ce réflexe pris, vos classes deviennent des petites forteresses propres, et vos futurs collègues (et vous-même dans 6 mois) vous remercieront !
