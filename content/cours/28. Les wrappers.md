On a vu qu'il existe deux catégories de types en Java : les [[8. Variables#Types|types primitifs]] (`int`, `double`, `boolean`, etc.) et les types objets. Mais parfois on a besoin de traiter un `int` comme un objet (par exemple dans une [[27. Les génériques|collection générique]]). C'est le rôle des **wrappers**. Petits mais costauds, ces types sont là pour faire le pont entre deux mondes !

## Qu'est-ce qu'un wrapper ?

Chaque type primitif a une classe **wrapper** associée :

| Primitif | Wrapper |
|:---|:---|
| `boolean` | `Boolean` |
| `byte` | `Byte` |
| `char` | `Character` |
| `short` | `Short` |
| `int` | `Integer` |
| `long` | `Long` |
| `float` | `Float` |
| `double` | `Double` |

```java
Integer number = Integer.valueOf(42); // box explicite
int value = number.intValue();         // unbox explicite
```

Un wrapper, c'est une "boîte" objet qui contient une valeur primitive. On peut le **boxer** (mettre la valeur dans la boîte) et le **unboxer** (sortir la valeur de la boîte). Simple, non ?

## Autoboxing et Unboxing

Depuis Java 5, la conversion entre primitifs et wrappers est **automatique** :

```java
Integer number = 42;  // autoboxing : int → Integer
int value = number;   // unboxing : Integer → int
```

Plus besoin d'appeler `valueOf()` ou `intValue()` à la main : le compilateur s'occupe de tout. On écrit le code naturellement, et le pont entre primitif et objet se fait tout seul !

```java
void main() {
  List<Integer> numbers = new ArrayList<>();
  numbers.add(10);      // autoboxing
  numbers.add(20);
  numbers.add(30);

  int sum = 0;
  for (int n : numbers) { // unboxing
    sum += n;
  }
  IO.println(sum); // 60
}
```

Regardez ce qui se passe dans l'ombre : `numbers.add(10)` transforme le `int` 10 en `Integer` avant de l'ajouter, et la boucle transforme chaque `Integer` en `int` pour l'ajouter à `sum`. Tout est transparent pour nous !

## Pourquoi des wrappers ?

### 1. Collections et génériques

Les collections ne peuvent stocker que des objets, pas des primitifs :

```java
// List<int> — erreur, int n'est pas un objet
List<Integer> numbers = new ArrayList<>(); // ok avec le wrapper
```

C'est la raison d'être n°1 des wrappers : les [[29. Les collections|collections]] et les [[27. Les génériques|génériques]] ne fonctionnent qu'avec des objets. Sans les wrappers, pas de `List<Integer>` !

### 2. Valeur null

Contrairement aux primitifs, les wrappers peuvent être `null` :

```java
Integer a = null;  // ok
int b = null;      // erreur

void process(Integer value) {
  if (value != null) {
    IO.println(value * 2);
  }
}
```

Utile quand une valeur est optionnelle (par exemple un champ de base de données qui peut être NULL). Un wrapper, c'est "une valeur, ou rien du tout" — un luxe que les primitifs ne peuvent pas se permettre !

### 3. Méthodes utilitaires

Les wrappers fournissent des méthodes statiques très pratiques :

```java
// Conversion String → nombre
int a = Integer.parseInt("42");
long b = Long.parseLong("123456789");
double c = Double.parseDouble("3.14");

// Comparaison
int compare = Integer.compare(10, 20);  // négatif

// Constantes
int maxInt = Integer.MAX_VALUE;   // 2147483647
int minInt = Integer.MIN_VALUE;   // -2147483648

// Formatage
String hex = Integer.toHexString(255);  // "ff"
String binary = Integer.toBinaryString(42); // "101010"
```

```java
// Character
char ch = 'A';
boolean isLetter = Character.isLetter(ch);   // true
boolean isDigit = Character.isDigit('5');    // true
boolean isUpper = Character.isUpperCase(ch); // true
char lower = Character.toLowerCase(ch);      // 'a'
```

Besoin de convertir un `String` en nombre ? `parseInt`. Vérifier qu'un caractère est un chiffre ? `isDigit`. Les wrappers sont de véritables boîtes à outils !

## Attention aux performances

L'autoboxing crée un objet à chaque conversion. Dans une boucle, ça peut coûter cher :

```java
// Lent : beaucoup d'allocations d'objets
Long sum = 0L; // Long, pas long !
for (long i = 0; i < 1_000_000; i++) {
  sum += i; // autoboxing + unboxing à chaque itération
}

// Rapide : pas d'objets
long sum = 0L;
for (long i = 0; i < 1_000_000; i++) {
  sum += i;
}
```

Un million d'objets créés puis jetés, ça finit par se voir. Dans les boucles serrées et les calculs lourds, restez sur les primitifs. Les wrappers, c'est pour la flexibilité, pas pour les performances !

## Attention aux références (piège classique)

Voici un piège qui a fait pleurer plus d'un développeur :

```java
Integer a = 100;
Integer b = 100;
IO.println(a == b); // true — cache pour les petites valeurs (-128 à 127)

Integer c = 200;
Integer d = 200;
IO.println(c == d); // false — deux objets différents !

// Toujours utiliser equals() pour comparer des wrappers
IO.println(a.equals(b)); // true
IO.println(c.equals(d)); // true
```

Pourquoi ce résultat surprenant ? Java met **en cache** les `Integer` entre -128 et 127 (configurable). Pour ces valeurs, `a` et `b` pointent vers le même objet en cache. Pour 200, hors de la plage, deux objets distincts sont créés. Résultat : `==` donne `true` dans un cas et `false` dans l'autre, avec un code pourtant identique !

La leçon est simple : **toujours comparer des wrappers avec `equals()`, jamais avec `==`**. On le rejoint sur ce point avec [[21. equals et hashCode|equals]] !

## Wrappers et immutabilité

Tous les wrappers sont [[30. Mutable et Immuable|immutables]]. Une fois créé, la valeur d'un wrapper ne peut pas changer.

```java
Integer x = 42;
x = x + 1; // un NOUVEL objet Integer est créé (43), l'ancien (42) est jeté
```

Comme pour les `String`, "modifier" un wrapper, c'est en créer un nouveau. L'ancien objet, lui, reste inchangé puis est éliminé par le ramasse-miettes.

## Valeurs par défaut

| Primitif | Valeur par défaut | Wrapper | Valeur par défaut |
|:---|:---|:---|:---|
| `int` | 0 | `Integer` | `null` |
| `boolean` | `false` | `Boolean` | `null` |
| `double` | 0.0 | `Double` | `null` |
| `char` | `'\u0000'` | `Character` | `null` |

C'est une différence importante quand on utilise les wrappers dans des objets :

```java
public class Person {
  private int age;         // 0 par défaut
  private Integer salary;  // null par défaut (pas de salaire = inconnu)
}
```

Un `null` peut signifier "valeur inconnue", là où un 0 pourrait être ambigu (est-ce que la personne a 0 ans ou n'a pas d'âge ?). Avec un `Integer`, on a un troisième état bien pratique : l'absence de valeur !

## Résumé

| Primitif | Wrapper | Quand utiliser le wrapper ? |
|:---|:---|:---|
| Plus rapide | Plus lent (objet) | Collections / génériques |
| Ne peut pas être `null` | Peut être `null` | Valeurs optionnelles |
| Pas de méthodes | Méthodes utilitaires | Conversion, parsing |
| `==` compare les valeurs | `equals()` pour comparer | Comparaison correcte |

Préférez les primitifs par défaut (performances, simplicité). Utilisez les wrappers quand vous avez besoin d'un objet (collections, `null`, génériques). C'est la règle d'or : chaque outil pour son usage !

Et comme les wrappers adorent les textes, enchaînons sur [[14. Les chaînes de caractères|un rappel bien utile]] !
