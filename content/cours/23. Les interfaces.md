Les interfaces sont un concept clé de Java. Si les [[22. Les classes abstraites|classes abstraites]] permettent de factoriser du code, les interfaces permettent de définir un **contrat** : ce qu'une classe doit savoir faire, sans dire comment. Imaginez un cahier des charges : on y écrit ce qu'il faut livrer, pas la façon de le construire !

## Qu'est-ce qu'une interface ?

Une interface déclare des méthodes **sans implémentation** (avant Java 8 en tout cas). Une classe qui **implémente** une interface s'engage à fournir le corps de toutes ses méthodes.

```java
public interface Flyable {
  void takeOff();
  void land();
  void fly();
}
```

```java
public class Bird implements Flyable {
  private String name;

  public Bird(String name) {
    this.name = name;
  }

  @Override
  public void takeOff() {
    IO.println(name + " s'envole !");
  }

  @Override
  public void land() {
    IO.println(name + " se pose.");
  }

  @Override
  public void fly() {
    IO.println(name + " vole dans le ciel.");
  }
}
```

```java
public class Airplane implements Flyable {
  private String model;

  public Airplane(String model) {
    this.model = model;
  }

  @Override
  public void takeOff() {
    IO.println(model + " décolle sur la piste.");
  }

  @Override
  public void land() {
    IO.println(model + " atterrit.");
  }

  @Override
  public void fly() {
    IO.println(model + " vole à 900 km/h.");
  }
}
```

L'interface `Flyable` dit juste "savoir voler", et chacun implémente ce savoir-faire à sa façon : l'oiseau bat des ailes, l'avion tourne ses réacteurs. Le contrat est le même, les comportements sont différents.

## Polymorphisme avec les interfaces

Comme pour les classes abstraites, on peut utiliser le polymorphisme :

```java
void main() {
  Flyable[] flyers = {
    new Bird("Piaf"),
    new Airplane("Boeing 747")
  };

  for (Flyable f : flyers) {
    f.takeOff();
    f.fly();
    f.land();
  }
}
```

On traite un oiseau et un avion de la même façon, parce qu'ils ont tous les deux signé le contrat `Flyable`. Le code qui les utilise n'a même pas besoin de savoir qui est quoi !

## Une classe peut implémenter plusieurs interfaces

C'est là que les interfaces sont **puissantes** : contrairement à l'héritage (une seule classe parente), on peut implémenter **plusieurs interfaces**.

```java
public interface Swimmable {
  void swim();
}

public interface Flyable {
  void fly();
}

public class Duck implements Flyable, Swimmable {
  @Override
  public void fly() {
    IO.println("Le canard vole.");
  }

  @Override
  public void swim() {
    IO.println("Le canard nage.");
  }
}
```

C'est la solution de Java au problème de l'**héritage multiple** (présent dans d'autres langages comme C++). Une classe ne peut étendre qu'une seule classe, mais peut implémenter autant d'interfaces qu'elle veut. Un canard, lui, vole ET nage. On est bien loin des limites d'un simple héritage !

## Interfaces et héritage

Une interface peut elle-même **étendre** une ou plusieurs autres interfaces :

```java
public interface Animal {
  void eat();
  void sleep();
}

public interface Pet extends Animal {
  void play();
}

public class Dog implements Pet {
  @Override
  public void eat() {
    IO.println("Le chien mange.");
  }

  @Override
  public void sleep() {
    IO.println("Le chien dort.");
  }

  @Override
  public void play() {
    IO.println("Le chien joue à la balle.");
  }
}
```

`Pet` hérite des exigences d'`Animal`, et la classe `Dog` doit tout fournir. Les contrats se composent et s'empilent à volonté.

## Méthodes par défaut (default)

Depuis Java 8, une interface peut avoir des méthodes avec un corps, grâce au mot clé `default`.

```java
public interface Flyable {
  void takeOff();
  void land();

  default void fly() {
    IO.println("L'objet vole.");
  }
}
```

Les classes qui implémentent `Flyable` peuvent utiliser la méthode `fly` par défaut ou la redéfinir si elles veulent un comportement différent.

```java
public class Bird implements Flyable {
  // pas besoin de redéfinir fly() si le comportement par défaut convient
  // mais on doit quand même implémenter takeOff() et land()
}
```

Utile pour **ajouter une méthode à une interface sans casser toutes les classes qui l'implémentent**. Avant ça, ajouter une méthode à une interface obligeait à tout modifier ; maintenant, on fournit une version par défaut et tout le monde continue de fonctionner !

## Méthodes statiques dans les interfaces

Depuis Java 8 aussi, on peut avoir des méthodes `static` dans une interface :

```java
public interface MathOperations {
  static int add(int a, int b) {
    return a + b;
  }
}

// Utilisation
int result = MathOperations.add(3, 4);
```

Comme pour les classes, `static` signifie qu'on appelle la méthode directement sur l'interface, sans passer par une instance.

## Interface vs classe abstraite

Le choix dépend du besoin. Pour vous aider, voici un petit tableau des situations types :

| Scénario | Solution |
|:---|:---|
| Partager du code (attributs, méthodes concrètes) | [[22. Les classes abstraites|Classe abstraite]] |
| Définir un contrat pur (que des méthodes à implémenter) | Interface |
| Une classe doit avoir plusieurs "rôles" | Interface (implémentation multiple) |
| Hiérarchie forte (un chien EST UN animal) | Classe abstraite |
| Capacité (un canard SAIT voler ET nager) | Interface |

En résumé : l'héritage dit *ce qu'on est*, l'interface dit *ce qu'on sait faire*. Gardez cette distinction en tête et le choix deviendra naturel.

## Les interfaces dans le JDK

Les interfaces sont partout dans le JDK :

- `List`, `Set`, `Map` → interfaces des [[29. Les collections|collections]]
- `Comparable` → pour définir un ordre naturel
- `Runnable` → pour exécuter du code dans un thread
- `Consumer`, `Function`, `Predicate` → [[31. La programmation fonctionnelle|interfaces fonctionnelles]]

```java
public class Person implements Comparable<Person> {
  private String name;
  private int age;

  @Override
  public int compareTo(Person other) {
    return Integer.compare(this.age, other.age);
  }
}
```

Ici, `Person` signe le contrat `Comparable<Person>` : elle promet de savoir se comparer à une autre personne, ici par l'âge. Résultat : on peut trier des listes de `Person` sans rien écrire de plus !

Vous commencez à voir le fil rouge : les interfaces structurent tout le JDK, et bientôt tout votre code. On continue avec [[26. Les classes internes|les classes internes]] !
