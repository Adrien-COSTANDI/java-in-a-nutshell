La programmation fonctionnelle est un paradigme qui considère les fonctions comme des valeurs qu'on peut passer en paramètre, retourner, et stocker. Et non, ce n'est pas réservé aux langages exotiques : Java 8 a introduit les **lambdas** et les **interfaces fonctionnelles** pour permettre ce style. Allez, on sort un peu de notre zone de confort, ça vaut le coup !

## Les interfaces fonctionnelles

Une **interface fonctionnelle** est une interface qui n'a **qu'une seule méthode abstraite**. On peut l'annoter avec `@FunctionalInterface` pour que le compilateur vérifie.

```java
@FunctionalInterface
public interface Greeter {
  String greet(String name);
  // une seule méthode abstraite
}
```

Une seule méthode, c'est le secret : c'est ce qui permet de l'implémenter avec une simple expression. Le JDK fournit des interfaces fonctionnelles prêtes à l'emploi dans `java.util.function` :

| Interface | Méthode | Description |
|:---|:---|:---|
| `Predicate<T>` | `boolean test(T t)` | Teste une condition |
| `Consumer<T>` | `void accept(T t)` | Consomme une valeur |
| `Function<T, R>` | `R apply(T t)` | Transforme une valeur |
| `Supplier<T>` | `T get()` | Fournit une valeur |
| `UnaryOperator<T>` | `T apply(T t)` | Transforme (même type) |
| `BinaryOperator<T>` | `T apply(T a, T b)` | Combine deux valeurs |

Retenez bien ces quatre-là : `Predicate`, `Consumer`, `Function`, `Supplier`. Vous les croiserez partout, et leurs noms décrivent exactement ce qu'elles font !

## Les expressions lambda

Une lambda est une façon concise d'implémenter une interface fonctionnelle.

```java
// Avant — classe anonyme
Greeter french = new Greeter() {
  @Override
  public String greet(String name) {
    return "Bonjour " + name;
  }
};

// Après — lambda
Greeter french = name -> "Bonjour " + name;
```

Regardez la différence : huit lignes réduites à une seule ! La lambda est la version moderne des [[26. Les classes internes#Classe anonyme|classes anonymes]]. Même idée, syntaxe allégée.

### Syntaxe

```java
// (paramètres) -> { corps }
// (paramètres) -> expression

// Un paramètre, sans parenthèses
Greeter g = name -> "Hello " + name;

// Plusieurs paramètres
BinaryOperator<Integer> add = (a, b) -> a + b;

// Avec type explicite
BinaryOperator<Integer> add = (Integer a, Integer b) -> a + b;

// Plusieurs instructions
Function<String, Integer> countLetters = s -> {
  int count = s.length();
  IO.println("Comptage effectué");
  return count;
};

// Aucun paramètre
Supplier<String> hello = () -> "Hello World!";
```

Quelques règles simples : un seul paramètre → pas de parenthèses ; une seule expression → pas de `return` ni d'accolades ; plusieurs instructions → accolades et `return` obligatoires. C'est tout !

### Exemples concrets

```java
void main() {
  List<String> names = List.of("Alice", "Bob", "Charlie");

  // Consumer : afficher chaque élément
  names.forEach(name -> IO.println(name));

  // Predicate : filtrer
  Predicate<String> startsWithA = s -> s.startsWith("A");
  for (String name : names) {
    if (startsWithA.test(name)) {
      IO.println(name + " commence par A");
    }
  }

  // Function : transformer
  Function<String, Integer> length = s -> s.length();
  for (String name : names) {
    IO.println(name + " a " + length.apply(name) + " lettres");
  }
}
```

On met une "machine" dans une variable : `startsWithA` teste une condition, `length` transforme une chaîne en nombre. La fonction est devenue un objet comme un autre, qu'on peut stocker et réutiliser !

## Méthodes références (method references)

Quand la lambda ne fait qu'appeler une méthode existante, on peut utiliser une **method reference** :

```java
// Lambda
names.forEach(name -> IO.println(name));

// Method reference
names.forEach(IO::println);
```

Syntaxe : `ClasseOuInstance::méthode`

```java
// méthode statique
Function<String, Integer> parseInt = Integer::parseInt;

// méthode d'instance sur un paramètre
Predicate<String> isEmpty = String::isEmpty;

// méthode d'instance sur un objet externe
Consumer<String> print = IO::println;

// constructeur
Supplier<List<String>> listCreator = ArrayList::new;
```

Le double deux-points `::` remplace la lambda quand elle ne fait qu'appeler une méthode. C'est plus court, et même plus lisible une fois qu'on a l'habitude !

## Interfaces fonctionnelles dans le JDK

### Predicate

```java
Predicate<Integer> isEven = n -> n % 2 == 0;
Predicate<Integer> isPositive = n -> n > 0;
Predicate<Integer> isEvenAndPositive = isEven.and(isPositive);

IO.println(isEvenAndPositive.test(4));  // true
IO.println(isEvenAndPositive.test(-2)); // false (pas positif)
```

Les prédicats se combinent avec `and`, `or`, `negate`. On assemble des conditions comme des briques !

### Function

```java
Function<String, String> toUpper = s -> s.toUpperCase();
Function<String, String> exclaim = s -> s + "!";
Function<String, String> shout = toUpper.andThen(exclaim);

IO.println(shout.apply("hello")); // HELLO!
```

`andThen` chaîne les transformations : d'abord en majuscules, puis on ajoute le point d'exclamation. Chaque étape est une petite brique indépendante !

### Consumer

```java
Consumer<String> print = s -> IO.print(s);
Consumer<String> printLn = s -> IO.println(s);
Consumer<String> printBoth = print.andThen(printLn);

printBoth.accept("Coucou"); // CoucouCoucou\n
```

### Supplier

```java
Supplier<Double> random = () -> Math.random();
IO.println(random.get());
```

Un `Supplier` ne prend rien et fournit une valeur : parfait pour générer des nombres aléatoires, des identifiants, ou tout ce qui peut être produit à la demande !

## Combinaisons avec les collections

Les lambdas sont très utilisées avec les [[29. Les collections|collections]] :

```java
List<Integer> numbers = new ArrayList<>(List.of(3, 1, 4, 1, 5, 9, 2, 6));

// Trier avec un Comparator (interface fonctionnelle)
numbers.sort((a, b) -> Integer.compare(a, b));

// ou avec method reference
numbers.sort(Integer::compareTo);

// Supprimer selon une condition
numbers.removeIf(n -> n < 5);

// Remplacer chaque élément
numbers.replaceAll(n -> n * 2);

IO.println(numbers);
```

Un tri, une suppression conditionnelle, une transformation — tout en quelques lignes, sans boucle à écrire. C'est la puissance de la programmation fonctionnelle : on dit *quoi* faire, pas *comment* le faire !

Les lambdas et les [[32. Les Streams|streams]] forment un duo redoutable pour manipuler des données de façon déclarative. On voit ça maintenant !
