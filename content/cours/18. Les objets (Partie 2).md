## Packages

Un package est un concept en Java qui nous permet de rassembler des classes entre elles. C'est utile pour organiser son code en différentes parties pour s'y retrouver plus facilement quand on a un projet de moyenne ou grande envergure. Un package est littéralement une suite de répertoires dans lequel on range une ou plusieurs classes.

Java utilise la notation reverse DNS (c'est l'inverse de l'adresse d'un site web). *Par exemple, si vous êtes chez Google, votre package commencera par* `com.google.nomdeprojet`

Par convention, les noms de package sont en minuscules et ne finissent pas par 's' ou un nombre.

Par exemple, si je code un logiciel marchand pour `amazoone.com` qui vend des articles de son catalogue à des clients depuis son stock, j'ai un certain nombre de concepts à appréhender. Un projet comme celui-ci peut être composé de dizaines, voire centaines, voire même milliers de classes (là c'est énorme !). Il serait judicieux de séparer certains des concepts pour mieux s'y retrouver.

L'idée est tout bêtement de faire des dossiers séparés selon comment on juge plus pratique de s'organiser.

On peut par exemple créer un package `com.amazoone.client` pour gérer les clients, leur connexion, leurs recommandations, leurs informations personnelles/bancaires... On peut aussi créer un package `com.amazoone.inventory` pour gérer les articles, les stocks, les livraisons...

C'est aussi pratique pour éviter que les classes aient des noms en doublons. Imaginez le nombre de classes Java qui doivent s'appeler `Player` si on prend en considération tous les jeux qui ont été codés en Java !

Voilà un exemple d'un programme nommé Splendor développé pour l'Université Gustave Eiffel (UGE) :

![[packagesExample.png]]

On voit plusieurs classes dans des packages différents. Par exemple, la classe `Player` est dans le package `fr.uge.splendor.game`. Son nom complet (Fully Qualified Name, ou **FQN**) est `fr.uge.splendor.game.Player`. Ça peut être pratique de la désigner par son FQN dans le cas où plusieurs classes pourraient avoir le même nom dans le projet. Ainsi, on évite les doublons !

On déclare un package tout en haut d'une classe avec une ligne `{java} package fr.uge.splendor.game;`

```java title:Player.java
package fr.uge.splendor.game;

public class Player {

  private String name;

  public Player(String name) {
    this.name = name;
  }

  public String name() {
    return name;
  }

  @Override
  public String toString() {
    return "Player[" + "name=" + name + ']';
  }

}
```

Il faut que le nom du package au dessus de la classe soit cohérent avec sa position dans les dossiers, sinon le compilateur vous signalera une erreur pour déplacer la classe dans le bon dossier ou bien renommer le package déclaré.

## Visibilité

La notion de visibilité est au cœur des classes en Java. Dans la première partie sur les objets, je vous avais demandé de me faire confiance quand on voyait des `{java} public` ou `{java} private`, mais il est temps de vous donner les clés pour comprendre les raisons de leur présence...

En Java, il existe 4 visibilités différentes, chacune avec ses spécificités :
- `{java} public`
- `{java} private`
- `{java} package`
- `{java} protected` (on l'évoquera plus tard)

Ces visibilités peuvent concerner différentes choses dans nos programmes :
- le contenu des classes (champs, méthodes, constructeurs)
- les classes elles-mêmes

Cela signifie littéralement que nous pouvons "voir" ou non les classes ou leur contenu quand on programme.

Par exemple, si vous reprenez l'exemple de la classe `{java} Person` :

```java title:Person.java hl:private,public
public class Person {

  private String firstName;
  private String lastName;
  private int age;

  public Person(String firstName, String lastName, int age) {
    this.firstName = firstName;
    this.lastName = lastName;
    this.age = age;
  }

  public boolean isMinor() {
    return this.age < 18;
  }

  public void birthday() {
    this.age++;
  }

  @Override
  public String toString() {
    return this.firstName + " " + this.lastName + " is " + this.age + " years old.";
  }
}
```

Ici, on voit la présence des visibilités sur les lignes surlignées.

### Visibilité des classes

Commençons dans l'ordre d'apparition. À la première ligne `{java} public class Person`, le mot clé `{java} public` signifie que la classe est visible depuis n'importe où dans notre programme. C'est la visibilité que vous verrez le plus souvent sur des classes.

En opposition, j'aurais pu la déclarer en visibilité `{java} package`, ce qui lui permettrait de n'être visible que par les classes situées dans le même package (le même dossier).

Voilà un exemple simplifié avec des classes vides, juste pour illustrer :
![[packageVisibilityExample.png]]

```java title:MyPublicClass.java
package package1;

public class MyPublicClass {

  // ici je ne peux pas utiliser MyPackageClass
}
```

```java title:MyPackageClass.java
package package2;

class MyPackageClass { // absence de visibilité public explicite à cette ligne

  // ici je peux utiliser MyPublicClass
}
```

Pour déclarer une classe en visibilité package, il suffit de ne pas écrire qu'elle est `{java} public`, c'est la visibilité par défaut lorsque rien n'est précisé.

### Visibilité des membres des classes

Ensuite, on peut parler de visibilité pour les membres d'une classe. Lorsque l'on déclare des champs ou des méthodes, on peut aussi leur attribuer différentes visibilités :
- `{java} public`
- `{java} private`
- `{java} package`
- `{java} protected` (on l'évoquera plus tard)

```java title:Example1.java
package package1;

public class Example1 {

  public int a;
  private int b;
  int c; // visibilité package par défaut
}
```

Les membres déclarés `{java} public` sont visibles par toutes les classes qui ont accès à la classe `{java} Example` (tout le monde, puisque la classe est elle-même `{java} public`). Les membres déclarés `{java} private` ne sont visibles par personne sauf la classe `{java} Example` elle-même. Les membres déclarés sans visibilité ont une visibilité `{java} package` et sont visibles par toutes les classes qui sont présentes dans le même package.

## static

Dans une classe, on a vu qu'on pouvait définir des attributs et des méthodes pour les instances. Mais comment on fait si on n'a pas besoin d'une instance dans certains cas ? Ou alors si certaines données ne concernent aucune instance en particulier ?

Tenez, par exemple, si on prend une classe pour représenter une commande dans un magasin de e-commerce :

```java title:Order.java
public class Order {

  private static long nextId = 1; // partagé par toutes les instances avec static
  private long id;
  private String customerName;

  public Order(String customerName) {
    this.id = Order.nextId; // accès à la variable statique
    Order.nextId++; // on passe au suivant pour le prochain
    this.customerName = customerName;
  }

  public static void skipNextId() {
    Order.nextId++; // celui-là ne sera pas utilisé
  }

  public long getId() {
    return id;
  }

  public String getCustomerName() {
    return customerName;
  }

  @Override
  public String toString() {
    return "Order #" + id + " for " + customerName;
  }
}
```

Pour accéder aux champs `static` d'une classe, on passe par le nom de la classe puis le nom de l'attribut ou de la méthode à utiliser. `{java} Order.skipNextId()` permet d'incrémenter le compteur pour les identifiants manuellement. Comme ça, lors du prochain appel au constructeur, `{java} this.id = Order.nextId` prendra la valeur suivante !

En résumé : `static`, c'est le mot clé qui fait passer un membre de "appartient à chaque instance" à "appartient à la classe elle-même". Un compteur partagé, une constante commune, une méthode utilitaire... tout ça vit sans avoir besoin d'une instance.

## Héritage

L'héritage est un concept fondamental de la programmation orientée objet. Il permet à une classe d'**hériter** des caractéristiques (attributs et méthodes) d'une autre classe.

Imaginez que vous avez une classe `Animal` avec des attributs comme `name` et `age`, et des méthodes comme `eat()` et `sleep()`. Si vous voulez créer une classe `Dog` et une classe `Cat`, vous seriez obligé de réécrire tout le code de `Animal` dans chaque classe... Quel cauchemar !

Grâce à l'héritage, on va pouvoir dire que `Dog` **étend** `Animal` et récupère automatiquement tout son code :

```java
public class Animal {

  protected String name;
  protected int age;

  public Animal(String name, int age) {
    this.name = name;
    this.age = age;
  }

  public void eat() {
    IO.println(name + " mange.");
  }

  public void sleep() {
    IO.println(name + " dort.");
  }
}
```

```java
public class Dog extends Animal {

  public Dog(String name, int age) {
    super(name, age);
  }

  public void bark() {
    IO.println(name + " aboie !");
  }
}
```

```java
void main() {
  Dog dog = new Dog("Rex", 3);
  dog.eat();   // hérité de Animal
  dog.sleep(); // hérité de Animal
  dog.bark();  // propre à Dog
}
```

### extends

`extends` est le mot clé qui déclare l'héritage. `Dog extends Animal` signifie que `Dog` est une **sous-classe** (ou classe fille) de `Animal`, et `Animal` est la **super-classe** (ou classe mère) de `Dog`.

Grâce à ça, un `Dog` a accès à tous les membres `public` et `protected` de `Animal`.

### `protected`

Vous avez remarqué `protected` dans les attributs de `Animal` ? C'est la 4ème visibilité qu'on avait laissée de côté plus tôt ! La voilà, elle se situe entre `public` et `package` :

- `public` → visible partout
- `protected` → visible dans le même package **+** dans les sous-classes (même dans un autre package)
- `package` → visible dans le même package seulement
- `private` → visible dans la classe seulement

`protected` est très utile dans le cadre de l'héritage : on veut que les sous-classes accèdent aux attributs de la classe mère sans les rendre `public` à tout le monde.

### `super`

Le mot clé `super` permet de faire référence à la classe parente. On l'utilise principalement pour deux choses :

1. **Appeler le constructeur de la classe mère** : `super(name, age)` — obligatoire si la classe mère n'a pas de constructeur sans paramètres.
2. **Appeler une méthode de la classe mère** : `super.toString()`.

```java
public class Dog extends Animal {

  public Dog(String name, int age) {
    super(name, age);
  }

  @Override
  public String toString() {
    return "Chien : " + super.toString();
  }
}
```

### La classe `Object`

Toutes les classes en Java héritent **implicitement** de la classe `Object`. Même si vous n'écrivez pas `extends Object`, le compilateur le fait pour vous.

C'est pour ça que des méthodes comme `toString()`, `equals()`, `hashCode()` existent dans toutes les classes : elles sont définies dans `Object` et héritées automatiquement.

`Object` est la racine de toute la hiérarchie des classes en Java. Peu importe la classe que vous créez, elle descend toujours d'`Object`.

### Redéfinir une méthode (`@Override`)

On en a déjà parlé avec `toString()` dans la partie 1, mais maintenant vous avez le contexte complet. Quand une classe fille n'est pas satisfaite du comportement d'une méthode héritée, elle peut la **redéfinir** (on dit aussi "surcharger" ou "override").

```java
public class Animal {
  public void makeSound() {
    IO.println("L'animal fait un bruit.");
  }
}

public class Dog extends Animal {
  @Override
  public void makeSound() {
    IO.println("Le chien aboie !");
  }
}
```

Le `@Override` n'est pas obligatoire, mais il est **très fortement recommandé**. Il permet de :
- vérifier que la méthode existe bien dans la classe parente (le compilateur signale une erreur si le nom est incorrect)
- rendre explicite votre intention de redéfinir une méthode

### Héritage et constructeurs

Quand vous créez une instance d'une classe fille, le constructeur de la classe mère est **toujours** appelé. Si la classe mère a un constructeur sans paramètres, c'est automatique. Sinon, vous devez appeler `super(…)` explicitement **en première ligne** de votre constructeur.

### `sealed` (classes scellées)

Depuis Java 17, on peut restreindre les classes autorisées à hériter avec le mot clé `sealed`. Une classe `sealed` doit déclarer explicitement ses sous-classes avec `permits`.

```java
public sealed class Shape permits Circle, Rectangle, Triangle {
  // ...
}

public final class Circle extends Shape { }
public final class Rectangle extends Shape { }
public final class Triangle extends Shape { }
```

Ici, seules `Circle`, `Rectangle` et `Triangle` peuvent hériter de `Shape`. Toute autre tentative sera refusée par le compilateur. Les sous-classes d'une classe `sealed` doivent être `final`, `sealed` ou `non-sealed`. On verra que cette fonctionnalité est redoutable quand on la combine avec le [[33. Le pattern matching|pattern matching]] !

## `final`

Le mot clé `final` a plusieurs usages, mais l'idée générale est la même : **une fois défini, on ne peut plus le changer**.

### `final` sur une variable

Une variable déclarée `final` ne peut être réassignée. C'est une constante.

```java
final int MAX_SPEED = 120;
MAX_SPEED = 150; // erreur !
```

Par convention, on nomme les constantes en MAJUSCULES avec des underscores.

### `final` sur un attribut

Un attribut `final` doit être initialisé **au moment de la déclaration** ou **dans le constructeur**, et ne peut plus être modifié ensuite.

```java
public class Person {
  private final String firstName;

  public Person(String firstName) {
    this.firstName = firstName; // ok
  }
}
```

Couplé avec `static`, on obtient une constante partagée par toutes les instances :

```java
public class MathUtils {
  public static final double PI = 3.14159265359;
}
```

C'est exactement ce que le commentaire du `static` sous-entendait : `final` empêche la réassignation.

### `final` sur une méthode

Une méthode `final` ne peut pas être redéfinie par une sous-classe.

```java
public class Animal {
  public final void breathe() {
    IO.println("…respire…");
  }
}

public class Dog extends Animal {
  @Override
  public void breathe() { } // erreur !
}
```

On utilise ça pour verrouiller un comportement qu'on ne veut pas voir modifié.

### `final` sur une classe

Une classe `final` ne peut pas être étendue.

```java
public final class MathUtils { }

public class ExtendedMath extends MathUtils { } // erreur !
```

C'est le cas de nombreuses classes du JDK comme `String`, `Integer` ou `Double`. Pour des raisons de sécurité et de performance : si n'importe qui pouvait modifier le comportement de `String`, tout le système pourrait dysfonctionner.

### Résumé de `final`

| Usage | Effet |
|:---|:---|
| `final` variable | ne peut pas être réassignée |
| `final` attribut | initialisé une seule fois |
| `final` méthode | ne peut pas être redéfinie |
| `final` classe | ne peut pas être étendue |
