Dans la vraie vie, on ne code jamais tout de zéro. On utilise des **librairies** et des **frameworks** qui fournissent des fonctionnalités toutes faites. C'est ce qui nous fait gagner un temps précieux : pourquoi réécrire une solution qui existe déjà et qui est testée par des milliers de développeurs ?

## Librairie vs Framework

| Librairie | Framework |
|:---|:---|
| Ensemble de classes qu'on **appelle** | Une structure qui nous **appelle** |
| On choisit quoi utiliser | On suit ses conventions |
| Exemple : `Apache Commons` | Exemple : `Spring` |

> "Your code calls a library. A framework calls your code."

La différence est toute simple : avec une librairie, c'est vous qui menez la danse ; avec un framework, c'est lui qui vous invite sur la piste et vous impose le tempo. Retenez cette citation, elle résume tout !

## Le JDK, une immense librairie

Le [[3. JRE ou JDK#JDK|JDK]] contient déjà des milliers de classes prêtes à l'emploi dans des packages standard :

```java
java.lang          // String, Math, Integer, System (importé automatiquement)
java.util          // List, Map, Set, Collections, Random
java.io            // Lecture/écriture de fichiers
java.nio.file      // Nouvelle API fichiers
java.time          // Dates (LocalDate, LocalDateTime, etc.)
java.net           // Réseau, URL
java.sql           // Base de données
java.util.function // Interfaces fonctionnelles
java.util.stream   // Stream API
```

Avant de chercher une librairie externe, pensez d'abord au JDK : il couvre déjà énormément de besoins. Les collections, les streams, les dates, les fichiers... tout est là, gratuit et maintenu par Oracle !

## Installer une librairie externe

### Avec Maven

Maven est un outil de **gestion de dépendances** (et bien plus). On déclare ses librairies dans un fichier `pom.xml` :

```xml
<dependencies>
  <dependency>
    <groupId>com.google.code.gson</groupId>
    <artifactId>gson</artifactId>
    <version>2.10.1</version>
  </dependency>
</dependencies>
```

Maven télécharge automatiquement la librairie et ses dépendances depuis un dépôt central. Vous déclarez ce qu'il vous faut, il s'occupe du reste !

### Avec Gradle

Gradle est un autre outil, plus moderne, avec un fichier `build.gradle` :

```gradle
dependencies {
  implementation 'com.google.code.gson:gson:2.10.1'
}
```

Une seule ligne ! Choisissez votre outil, les deux font le même travail : gérer vos dépendances comme un chef.

### Sans outil (manuellement)

On télécharge le `.jar` et on l'ajoute au classpath du projet. C'est faisable mais fastidieux, et surtout très vite ingérable quand on a 20 dépendances interdépendantes. C'est exactement pour ça que Maven et Gradle existent !

## Les librairies populaires en Java

### Gson / Jackson — JSON

```java
// Gson
Gson gson = new Gson();
String json = gson.toJson(new Person("Alice", 30));
Person p = gson.fromJson(json, Person.class);
```

Convertir un objet en JSON, et un JSON en objet : deux lignes. C'est le genre de chose qu'on ne réinvente pas soi-même !

### Apache Commons — Utilitaires

```java
String reversed = StringUtils.reverse("Hello"); // "olleH"
boolean isBlank = StringUtils.isBlank("   ");   // true
```

Des dizaines de petites fonctions utilitaires qui vous évitent d'écrire des méthodes que tout le monde a déjà écrites.

### JUnit — Tests

```java
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

class CalculatorTest {
  @Test
  void testAdd() {
    assertEquals(5, Calculator.add(2, 3));
  }
}
```

Tester son code est indispensable, et JUnit est LE standard pour ça. On écrira des tests partout, croyez-moi !

### Hibernate — Base de données (ORM)

```java
@Entity
public class Person {
  @Id
  @GeneratedValue
  private Long id;
  private String name;
}
```

Hibernate relie vos classes Java à vos tables de base de données. Les annotations disent "cette classe correspond à une table, cet attribut est la clé primaire" et le framework s'occupe du reste !

### Spring — Framework complet

Spring est le framework le plus utilisé en Java pour créer des applications web et des microservices :

```java
@RestController
public class HelloController {
  @GetMapping("/hello")
  public String hello() {
    return "Hello World!";
  }
}
```

Quelques annotations et votre méthode devient une API web accessible sur `/hello`. Spring gère tout le côté réseau, HTTP et JSON pour vous !

## Les frameworks de build

| Outil | Description |
|:---|:---|
| **Maven** | Standard de fait, XML, plus verbeux |
| **Gradle** | Plus moderne, Groovy/Kotlin DSL, plus rapide |

Les deux gèrent :
- les dépendances
- la compilation
- les tests
- le packaging (JAR, WAR)
- le déploiement

Un build tool, c'est le majordome de votre projet : il compile, teste, empaquette et déploie, pendant que vous écrivez du code !

## Les JARs

Un **JAR** (Java ARchive) est un fichier `.jar` qui contient des classes Java compilées, compressées (format ZIP). C'est le format de distribution des librairies Java.

```bash
# Créer un JAR
jar cf monApp.jar -C bin/ .

# Lancer un JAR exécutable
java -jar monApp.jar
```

Un JAR, c'est votre application (ou votre librairie) emballée dans une boîte prête à être distribuée. Tout le monde peut la déballer et l'utiliser !

## Comment trouver une librairie ?

1. **Maven Central** (search.maven.org) — le dépôt officiel
2. **GitHub** — beaucoup de projets open source
3. **Baeldung** — tutoriaux avec exemples

```java
// Exemple avec une librairie de logs (SLF4J + Logback)
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class MyApp {
  private static final Logger log = LoggerFactory.getLogger(MyApp.class);

  void main() {
    log.info("L'application démarre");
    try {
      // du code risqué
    } catch (Exception e) {
      log.error("Une erreur est survenue", e);
    }
  }
}
```

Un dernier exemple avec SLF4J, la librairie de logs : on garde la trace de ce qui se passe dans l'application. À la place du `System.out.println`, on utilise des niveaux (`info`, `error`...) pour filtrer les messages selon leur importance. Et dans le `catch`, on passe l'exception au logger pour qu'elle soit consignée avec sa pile d'erreurs complète !

## Conclusion

Savoir utiliser des librairies et des frameworks est une compétence essentielle. Le JDK couvre déjà beaucoup de besoins, mais pour des fonctionnalités spécialisées (JSON, base de données, web, tests), une librairie externe est souvent la solution.

Ne réinventez pas la roue : si quelqu'un a déjà résolu un problème, utilisez sa solution !
